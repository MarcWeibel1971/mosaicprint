# Plan: Auth, Projekt-Speicherung & QR-Codes

## Übersicht

Drei zusammenhängende Features:
1. **User Registration/Auth** — Basis für alles
2. **Projekt-Speicherung** — localStorage → Server (mit User-Account)
3. **QR-Code für Events** — Auto-generiert, in Event-Detail angezeigt

---

## Phase 1: User Authentication

### 1a. Packages installieren
- `bcryptjs` (Passwort-Hashing)
- `jsonwebtoken` (JWT-Token)
- `qrcode` (QR-Code Generierung)

### 1b. Datenbank: `users` Tabelle
```sql
CREATE TABLE IF NOT EXISTS users (
  id SERIAL PRIMARY KEY,
  email TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  display_name TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
)
```

### 1c. Server: Auth-Endpunkte
- `POST /api/auth/register` — E-Mail + Passwort + Name → User + JWT
- `POST /api/auth/login` — E-Mail + Passwort → JWT
- `GET /api/auth/me` — JWT → User-Daten
- Auth-Middleware: `requireAuth(req, res, next)` prüft JWT aus `Authorization: Bearer ...`

### 1d. Client: Auth-Pages & Context
- `AuthContext` — globaler Auth-State (user, token, login, logout, register)
- `/login` — Login-Seite
- `/register` — Registrierungs-Seite
- Navbar: Login/Register-Buttons oder User-Name + Logout
- Token wird in `localStorage` gespeichert

## Phase 2: Projekt-Speicherung (Server-seitig)

### 2a. Datenbank: `projects` Tabelle
```sql
CREATE TABLE IF NOT EXISTS projects (
  id SERIAL PRIMARY KEY,
  user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name TEXT NOT NULL DEFAULT 'Mein Mosaik',
  data JSONB NOT NULL,
  thumbnail_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
)
```

### 2b. Server: Projekt-Endpunkte
- `POST /api/projects` (auth) — Neues Projekt speichern
- `GET /api/projects` (auth) — Alle Projekte des Users
- `GET /api/projects/:id` (auth) — Einzelnes Projekt laden
- `PUT /api/projects/:id` (auth) — Projekt aktualisieren
- `DELETE /api/projects/:id` (auth) — Projekt löschen

### 2c. Client: Studio-Integration
- `saveProject()` speichert auf Server statt localStorage (wenn eingeloggt)
- Fallback: localStorage für nicht-eingeloggte User
- Neue Seite `/projekte` — Projektliste mit Thumbnails
- Im Studio: "Meine Projekte" Button zum Laden gespeicherter Projekte

---

## Phase 3: QR-Code für Events

### 3a. Server: QR-Code Endpunkt
- `GET /api/events/:slug/qr` — generiert QR-Code als PNG/SVG
- URL im QR-Code: `{APP_URL}/event/{slug}`

### 3b. Client: QR-Anzeige
- EventsTab (Admin): QR-Code Button → zeigt QR-Code als Modal/Inline
- Events-Seite (Frontend): QR-Code Download-Button pro Event
- EventPage: Optional QR-Code zum Teilen

### 3c. Event-Ownership (user_id)
- `mosaic_events` bekommt `user_id` Spalte (nullable für Rückwärtskompatibilität)
- Eingeloggte User sehen ihre Events auf `/events`
- Nicht-eingeloggte können weiterhin Events über den Slug besuchen
